# Caret v0.1.2 更新日志

发布日期：2026-07-19

## 第一部分：业务改进（通俗版）

### 1. 修复“正确许可证仍然激活失败”

客户端现在会识别并保存当前授权服务器的公钥，不再因为打包电脑与实际授权电脑使用了不同公钥而错误地拒绝正确许可证。

### 2. 许可证可以随时重新复制

管理员不必只在创建许可证的一瞬间保存密钥。许可证列表增加了“复制许可”按钮，以后忘记时可以重新复制。

### 3. 兼容旧版许可证数据

旧版许可证会继续保留；由于旧版只保存了无法逆向恢复的密钥哈希，管理员可在复制时选择生成一个新密钥，已经激活的设备不会因此立即失效。

### 4. 导出结果更容易找到

导出成功后会明确显示导出路径；没有指定位置时，文件统一放在原文档目录下的 `Caret` 文件夹中。

### 5. 审校进度不会因切换页面消失

AI 审校进度由全局任务状态驱动，从文档库切换到设置页再返回时，仍能继续看到当前进度。

### 6. 发布目录和版本结构更清晰

当前交付包、历史版本和构建中间文件已分开收纳，发布根目录不再散落安装程序和临时文件。

## 第二部分：技术修改详情

### 许可证公钥与验签

- 激活和刷新响应新增 `public_key_pem` 与 `key_fingerprint`。
- 客户端首次激活时使用响应公钥验证同一响应中的 Ed25519 凭证，验签成功后将服务器公钥随本地凭证通过 Electron safeStorage 加密保存。
- 后续离线启动、心跳和刷新优先使用已固定的服务器公钥；刷新响应不能静默替换已经固定的公钥。
- 内置 `app/desktop/resources/license-public.pem` 仅作为升级前旧凭证的兼容回退，不再要求实际授权端与构建机提前共用同一密钥对。
- 新增“构建期内置公钥与服务器公钥不一致时仍可首次激活”的自动化回归测试。

### 许可证密钥重复复制

- `licenses` 表新增 `license_key_encrypted` 字段，并在启动时为旧 SQLite 数据库自动补列。
- 完整许可证密钥使用 AES-GCM 加密；独立保管键在 Windows 下由 DPAPI 保护。数据库仍保留 SHA256 哈希用于激活查询，列表和日志只展示脱敏前缀。
- 新增 `GET /api/v1/admin/licenses/{id}/key` 和 `POST /api/v1/admin/licenses/{id}/reset-key`。
- 管理页许可证列表新增“复制许可”按钮；旧记录没有可恢复密文时，界面会说明原因并提供“重置并复制新密钥”。

### 导出与审校进度

- 导出默认目录统一为输入文档所在目录下的 `Caret` 子目录，导出成功消息携带完整输出路径。
- 审校任务进度迁移到跨页面共享状态，页面重新挂载时从当前任务状态恢复进度展示。

### 发布工程化

- 版本升级为 `0.1.2`，重新构建 Python 后端、Caret License Center 和 Electron NSIS 安装程序。
- 发布前烟测覆盖：打包后端健康与版本、授权端随机新密钥、许可证创建、重复复制、激活响应公钥和管理页按钮。
- 发布 ZIP 使用 UTF-8 中文路径，并对 ZIP CRC、文件清单和逐文件 SHA256 进行核对。
- 旧代码继续保持只读隔离，边界检查确认桌面包不包含 `legacy/` 与 `archive/`。
